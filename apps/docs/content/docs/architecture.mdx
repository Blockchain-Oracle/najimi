## The repository

A pnpm and Turborepo monorepo:

| Path | What |
| --- | --- |
| `apps/web` | The product: pages, API routes, cards, the landing, link previews. |
| `apps/worker` | Every slow job, the schedules and the push sender. Runs migrations at start. |
| `apps/social-bridge` | Instagram for the worker (Python, internal, stateless). |
| `apps/docs` | This site (Fumadocs, a static export). |
| `packages/qloo` | The Qloo client: caching, a concurrency limiter, call logging, taste and explore helpers. |
| `packages/agent` | The agent: rules, tools, turns, business plans, booking follow-ups. |
| `packages/booking` | Plans, routes, shows, Nuitee, phone calls, calendar files. |
| `packages/connectors` | Imports, the daily tune-up, X (rettiwt-api), sealed sessions, the bridge client. |
| `packages/games` | Rounds built from Qloo with hidden answers, scoring, the daily drop. |
| `packages/geo` | Geohash squares, polygons, distances. |
| `packages/db` | Schema, migrations, moving a guest's data on sign-in, deleting everything. |
| `packages/live`, `jobs`, `sources`, `media`, `storage`, `config`, `env`, `tokens`, `ui` | Live events, queues, outside fetching and caching, images, storage, every tunable, typed env, design tokens, components. |

## Rooms and the agent

Every chat (yours with Najimi, a DM, a circle) is a room with its own messages table. A message is saved, announced on the room's live topic, and if it calls Najimi, an agent turn is queued for the worker, one turn per room at a time. The turn streams its answer to everyone in the room through the same live pipe, so it finishes even if everyone leaves.

## The live pipe

One Postgres channel carries every live event. Each event is a row (`live_events`) written in the same transaction as its announcement, so nobody hears about a row they can't read yet. Topics are `room:<id>`, `run:<id>` (a visible run, like a plan being built) and `user:<id>` (your own news). A page that reconnects replays what it missed by id. The worker listens on the same channel to turn your news into Web Push.

## Taste

A person's taste is their loves with weights. Qloo turns it into picks per kind (with explainability: which love led to which pick), words, and where it lives in a city. A circle's taste is its members' loves blended so each member counts the same. A business's taste is its own Qloo entity, or the places most like it. The same lenses (feed, map, graph, games, plans) take any of them.

## Real, not pretend

There's no demo mode. Hotel bookings are real Nuitee bookings; calls ring real venues; posts go out from your real account. Everything that costs money or acts in your name waits for your yes, has a daily allowance, and is logged.

## Running it

Everything runs on one Coolify server: web, worker, social bridge, docs and Postgres. The worker applies migrations at start. The web app keeps gzip off on purpose (it would hold back live events).
